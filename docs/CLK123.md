# CLK123 — nested tracking

Creator briefs and link shorteners often paste a full tagged landing URL into
`utm_content`, `utm_term`, or a wrapper such as `redirect=`. GA4 then stores the
wrapper string instead of the intended campaign dimension, and inner UTM pairs
never become the page query string.

`creator_link_kit.nested.find_nested_tracking` flags:

- a `utm_*` value that is itself an `http(s)://` URL
- a `utm_*` value that embeds another `utm_source=` / `utm_campaign=` pair
- a non-UTM wrapper whose value contains UTM pairs

It does **not** flag an ordinary `next=` / `ref=` URL with no UTM pairs, and it
does not flag stable placement IDs.

## Wire into audit (four lines)

In `validate_url`, after `pairs = parse_qsl(...)`:

```python
from .nested import find_nested_tracking

for parameter, message in find_nested_tracking(pairs):
    issues.append(Issue("CLK123", "error", message, parameter=parameter))
```

This module is shipped independently so the detector and tests can land without
rewriting `links.py`.
