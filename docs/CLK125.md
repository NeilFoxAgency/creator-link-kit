# CLK125 — UTM parameters on a public shortener host

## Problem

Creator briefs and description drafts often look like this:

```text
https://bit.ly/glowdrop?utm_source=youtube&utm_campaign=cmp-spring
```

The shortener is the *destination* of the tagged URL. Many public shorteners:

- strip unknown query parameters, or
- do not forward them to the brand landing page.

GA4 then records the shortener hostname, or attributes the session as
direct/none. The link still *looks* tracked.

This is different from:

- `CLK003` (destination not in `owned_domains`)
- platform-host rules that target YouTube / TikTok / Instagram video URLs
- paste-corruption rules (`CLK117`–`CLK123`) that inspect delimiter or
  character shape

## Detection

`creator_link_kit.shortener_utm.should_flag_shortener_utm` returns true when:

1. the hostname is a known public shortener root (or a subdomain of one),
2. the host is **not** listed in `owned_domains`, and
3. the query string contains at least one `utm_*` key.

`validate_url` and therefore `clk audit`, `clk build` final checks, batch
audits, and the GitHub Action all emit **CLK125** as an error.

## What is not flagged

- An owned shop URL with UTMs (`shop.example.com?...`).
- A shortener URL with **no** UTM keys (use CLK003 / CLK004 for those).
- A first-party short domain included in `owned_domains` (the brand controls
  forwarding).

## Operator fix

Put UTM parameters on the final owned landing URL. If a short link is still
required, configure the shortener to *append* those parameters on redirect,
or use a first-party short domain listed in `owned_domains`.
