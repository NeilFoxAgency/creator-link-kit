# CLK128 — glued UTM pairs

## Problem

Creator briefs and roster spreadsheets often concatenate UTM cells without
an `&`:

```text
https://shop.example.com/offer?utm_source=youtubeutm_medium=influencer&utm_campaign=cmp-spring
```

`urllib.parse.parse_qsl` and GA4 only split on `&` (and, after decoding,
`?`). The second key is absorbed into the previous value. The link looks
tagged. Attribution is not.

A related paste shape uses a space instead of `&`:

```text
https://shop.example.com/offer?utm_source=youtube utm_medium=influencer
```

## What CLK128 does

- Inspects the **raw query string** before parsing.
- Flags a standard UTM key (`utm_source`, `utm_medium`, `utm_campaign`,
  `utm_term`, `utm_content`, `utm_id`) that starts inside another pair
  with no `&`, `?`, `#`, or `;` delimiter.
- Also flags a space or tab used as the only separator between two
  standard UTM keys.
- Does **not** rewrite the URL.
- Does **not** flag `utm_content=video,short-form` (comma inside a value,
  no following `utm_*=`).
- Does **not** flag a clean ampersand-delimited query.

## Operator fix

Insert a bare `&` between pairs:

```text
utm_source=youtube&utm_medium=influencer
```
