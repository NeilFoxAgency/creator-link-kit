# Discount-code coverage (CLK203 / CLK204 / CLK205)

Creator campaigns often issue one unique store code per placement. `clk batch`
already refuses duplicate generated codes. After publish, operators still need
to check that the *live* URLs carry those codes.

## Usage

```text
clk audit --config creator-links.json --input live_links.csv --codes codes.csv
```

`codes.csv` should include a `discount_code` column (or the column named in
`batch.discount_code_column`). Identifier-only files are fine; no emails,
order totals, or customer data belong in this file.

## Rules

| Code | Severity | Meaning |
| --- | --- | --- |
| CLK203 | error | A planned code never appears as a discount/coupon/promo query value |
| CLK204 | warning | A shipped URL has a discount query value that is not on the plan |
| CLK205 | error | The codes file lists the same code more than once |

Matching is case-insensitive. Query keys inspected: `discount`,
`discount_code`, `code`, `coupon`, `coupon_code`, `promo`, `promo_code`,
`voucher`. Generic keys such as `id` or `ref` are ignored.

## Privacy

Offline only. The checker reads local CSVs and URL query strings. It does not
call shop APIs or inspect redemption counts.
