# CLK129 — paid-ad click identifiers

## Problem

Creator briefs and YouTube descriptions often reuse a URL copied from a
live Google Ads, Meta, TikTok, Microsoft, or similar paid campaign. Those
platforms append a click identifier:

```text
https://shop.example.com/offer?utm_source=youtube&utm_campaign=cmp-spring&gclid=EAIaIQobChMI
```

GA4 and similar tools treat the click ID as paid-channel evidence. The
session is attributed to Paid Search or Paid Social even though the
creator UTM pairs are present. The link looks tracked. Influencer
reporting is not.

## Behavior

`validate_url` inspects parsed query keys (case-insensitive) for a
conservative list:

`gclid`, `gclsrc`, `wbraid`, `gbraid`, `dclid`, `fbclid`, `msclkid`,
`ttclid`, `twclid`, `li_fat_id`, `epik`, `sccid`, `irclickid`, `yclid`.

A match is a **CLK129** error. The URL is not rewritten.

Values are not inspected. A placement ID or note that happens to contain
the substring `gclid` is allowed.

`clk audit`, `clk build` final checks, batch generation, and the GitHub
Action all surface CLK129 because they call `validate_url`.

## Operator fix

Strip the paid click IDs and keep only the governed UTM pairs on the
brand landing page. Do not paste auto-tagged ad URLs into creator
descriptions.
