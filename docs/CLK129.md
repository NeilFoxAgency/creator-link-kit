# CLK129 — UTM parameters in the URL path

## Problem

Creator briefs and CMS pretty-URL builders sometimes omit `?` when appending
UTM pairs:

```text
https://shop.example.com/offer/utm_source=youtube&utm_medium=influencer
```

`urllib.parse.urlsplit` treats everything after the host as the **path**.
`parse_qsl` and GA4 only read the query string. The link looks tagged.
Attribution is not.

This is different from:

- CLK118 — UTMs in the fragment (`#utm_source=...`)
- CLK119 — a second `?` inside an existing query
- CLK127 / CLK128 — wrong or missing delimiters *inside* a real query string

CLK129 inspects the **path**.

## Detection

Flag when the path contains a standard UTM assignment:

`utm_source=` `utm_medium=` `utm_campaign=` `utm_term=` `utm_content=` `utm_id=`

Case-insensitive. A path that only mentions UTMs in prose
(`/guides/what-is-utm-source`) is not flagged.

The URL is not rewritten.

## Operator fix

Insert `?` before the first UTM pair and `&` between pairs:

```text
https://shop.example.com/offer?utm_source=youtube&utm_medium=influencer
```
