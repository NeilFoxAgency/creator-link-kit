# CLK119 — percent-encoded UTM separators

Shipped creator links often arrive from Excel, Slack, or CMS exports with `&` encoded as `%26`:

```
https://shop.example.com/product?utm_source=youtube%26utm_medium=influencer&utm_campaign=cmp-spring-launch
```

`urllib.parse.parse_qsl` and GA4 split only on a raw `&`. The later UTM pair stays inside the earlier value, so medium/campaign attribution is silently lost.

This is distinct from CLK117 (HTML entities such as `&`) and CLK118 (UTM keys in the fragment).

## Detection

Error when either:

- the raw query contains `%26utm_` (case-insensitive), or
- a decoded query *value* matches `(?:[?&]|%26)utm_(source|medium|campaign|term|content|id)=`

Do not match a normal `?utm_source=` / `&utm_medium=` query string. Do not match an encoded ampersand that is not followed by a UTM key (`ref=a%26b`).

## Implementation

- Helper: `creator_link_kit.encoded_utm.has_encoded_utm_separator`
- Hook: `validate_url` in `links.py` after `parse_qsl`
