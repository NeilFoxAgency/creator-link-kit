# CLK119 — percent-encoded UTM separators

Shipped creator links often arrive from Excel, Slack, or CMS exports with
`&` stored as `%26`:

```
https://shop.example.com/product?utm_source=youtube%26utm_medium=influencer&utm_campaign=cmp-spring-launch
```

`parse_qsl` and GA4 split only on a raw `&`. The later UTM pair stays inside
the earlier value, so the description looks tagged while sessions attribute
as direct/none.

Creator Link Kit flags this as **CLK119**.

- `%26utm_` in the raw URL is an error.
- A decoded query value that contains another `&utm_source=` (or medium,
  campaign, term, content, id) pair is an error.
- A normal `?utm_` / `&utm_` query is not flagged.
- `%26` in a non-UTM value such as `sku%26color` is not flagged.
- HTML-entity separators (`&amp;`) remain **CLK117**.
- UTMs in the fragment (`#utm_`) remain **CLK118**.

This check is installed when the package is imported, so `validate_url`,
`audit_urls`, and `clk audit` all surface CLK119.
