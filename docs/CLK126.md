# CLK126 — UTM parameters on a video / social platform host

## Problem

Creator briefs and description drafts often look like this:

```text
https://youtu.be/dQw4w9WgXcQ?utm_source=youtube&utm_campaign=cmp-spring
```

The watch-page host is the *destination* of the tagged URL. YouTube, TikTok,
Instagram, and similar platforms do not forward those query keys to the brand
landing page. GA4 for the brand never records the campaign, even though the
link looks tagged.

This is different from:

- `CLK003` (destination not in `owned_domains`)
- `CLK125` (UTMs on a public shortener such as `bit.ly`)
- paste-corruption rules (`CLK117`–`CLK123`) that inspect delimiter or
  character shape

## Detection

`creator_link_kit.platform_utm.should_flag_platform_utm` returns true when:

1. the hostname is a known video/social platform root (or a subdomain of one),
2. the host is **not** listed in `owned_domains`, and
3. the query string contains at least one `utm_*` key.

`validate_url` and therefore `clk audit`, `clk build` final checks, batch
audits, and the GitHub Action all emit **CLK126** as an error.

## What is not flagged

- An owned shop URL with UTMs (`shop.example.com?...`).
- A platform URL with **no** UTM keys (use CLK003 / CLK004 for those).
- A first-party domain included in `owned_domains`.

## Operator fix

Put UTM parameters on the final owned landing URL. Keep the platform URL as
the *content* that hosts the CTA, not as the tagged destination.
