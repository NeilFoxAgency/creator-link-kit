# CLK127 — alternate query delimiters

## Problem

Creator briefs, ASP.NET-style URLs, and spreadsheet formulas sometimes separate
query pairs with `;` or `,` instead of `&`:

```text
https://shop.example.com/offer?utm_source=youtube;utm_medium=influencer;utm_campaign=cmp-spring
```

`urllib.parse.parse_qsl` and GA4 only split on `&`. Everything after the first
pair is stored as part of `utm_source`. The link looks tracked. Attribution is
not.

This is distinct from:

- CLK117 — HTML entities (`&amp;`)
- CLK119 — extra `?` characters
- CLK120 — percent-encoded `&` / `?` (`%26utm_`)
- CLK103 — the same key repeated after a real `&` split

## Rule

Emit **CLK127** (error) when the raw query string contains `;utm_*` or `,utm_*`
for a standard UTM key (`source`, `medium`, `campaign`, `term`, `content`, `id`).

Do not flag a comma or semicolon that is only inside a value
(`utm_content=video,short-form`).

Do not rewrite the URL.

## Operator fix

Replace `;` / `,` pair separators with `&` and re-audit before the link ships
in a description, QR code, or brief.
