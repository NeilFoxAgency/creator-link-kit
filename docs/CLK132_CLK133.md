# CLK132 and CLK133

These rules catch two paste failures that `urlsplit` does not treat as malformed URLs.

| Code | Severity | Problem |
| --- | --- | --- |
| `CLK132` | error | Raw URL contains whitespace (space, tab, newline, or Unicode separator) |
| `CLK133` | error | URL starts with a doubled `http(s)://` scheme from concatenation |

## Why they exist

Operators often copy links out of Sheets, Docs, or CMS fields.

- A wrapped cell or a Word NBSP leaves whitespace inside the URL. YouTube descriptions and QR encoders then split or percent-encode the link, so GA4 never sees the intended destination.
- Concatenating `https://` onto an already-absolute URL produces `https://https://shop.example.com/...`. `urlsplit` treats `https` as the hostname, so the real landing page never loads.

## Public API

`creator_link_kit.validate_url` and `creator_link_kit.audit_urls` include these checks. `clk audit` uses the same path. Callers that import `validate_url` from `creator_link_kit.links` directly still get the older parser-only behavior.

## Privacy

Checks are local string inspections. No network calls and no campaign data collection.
